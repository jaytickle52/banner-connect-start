BANNER CONNECT DEMOS: HOW THIS IS BUILT AND HOW TO UPDATE IT

The library is one player page plus data. Every demo is built from real screenshots
of the Banner Christian School sub-account. Nothing about a demo lives in the page code.

FILES
  index.html               The player and library page. Rarely changes.
  demos/library.json       The library: intro, "Talk to Banner 61" link, one card per demo
                           (job, title, summary, status "ready" or "coming-soon", plan label).
  tools/demos-src.json     THE FILE TO EDIT. Every demo's steps: which raw capture, the
                           highlighted box, the callout text, and small cover-ups.
  tools/build.py(.txt)     Turns demos-src.json + raw/ into screens/ and demos/<id>.json.
  raw/                     Original Chrome captures of the sub-account.
  screens/, demos/<id>.json  Generated by the build. Don't edit by hand.

EACH STEP IN tools/demos-src.json
  raw       Capture file in raw/.
  hotspot   Box to highlight, [left, top, right, bottom] in the capture's own pixels.
  edits     Optional cover-ups: "fill" a box with a color, "text" drawn on top, or
            "badge" (a round BCS crest in place of a logo).
  title, body, hint, alt   The callout text and screen-reader description.

COMMON UPDATES (ask Claude, pointing at this artifact)
  "Recapture the step 3 screen"   New file in raw/, adjust the hotspot, rebuild.
  "Reword step 2 of tours"        Edit the text in demos-src.json, rebuild.
  "Add a step" / "New demo"       Add to demos-src.json, set status "ready" in
                                  library.json, rebuild.
  "Label a feature as paid"       Set "plan" on that card in library.json.

DIRECT LINKS
  Artifact link plus #<demo-id>, e.g. ...#tour-scheduling. Use these in onboarding emails.
